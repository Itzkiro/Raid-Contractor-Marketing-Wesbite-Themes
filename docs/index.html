A Claude Code skill for websites on GitHub + Vercel. Type one command into your Claude Code session to add falling snow, pumpkins or hearts, a promo bar and an offer card. A date hardcoded into the code turns it all off for every visitor at the end date, with no redeploy.

What it installs

Three layers.
One date gate.

Each layer works on its own. All three check the same cutoff timestamp, so they appear together and disappear together.

  • 01
    Weather

    Falling emoji particles over every page, like the classic WordPress "falling elements" plugins. Pure CSS animation: no library, no network request.

  • 02
    Promo bar

    Your existing announcement bar gets a seasonal gradient and promo headline. Your normal bar is the fallback branch, so it comes back automatically after the end date.

    Re-skinAuto-revert--promo
  • 03
    Offer card

    A promo card on your offers or landing page, with price, commitment, exclusions and end date printed right beside the claim.

Quick start

GitHub → Claude
→ Vercel.

Your site's code lives in a GitHub repo, Vercel deploys it, and you make changes from a Claude Code cloud session (claude.ai/code or the Claude app) attached to that repo. Everything below happens in that session. There's no local terminal.

01

Install once

Paste the install prompt into a session on your website repo. Claude adds one file, .claude/skills/seasonal-theme/SKILL.md, commits it and pushes. Merge that into main.

02

Start a new session

Skills are read when a session starts, so open a fresh one on the repo after the skill is on main.

03

Ask for a season

Type the slash command, or ask in plain words ("make it snow until New Year's").

>/seasonal-theme christmas --promo "Holiday deal: first month $1" --promo-href /offers --terms "$1 month one, then $49/mo; 12-month commitment; new customers only"
04

Preview, then merge

Claude scouts the repo, works out the UTC cutoff, installs the components, checks them in a headless browser with a live and a faked future clock, and pushes to its branch. Vercel builds a preview URL for that branch. Check it there, then merge to main to go to production.

Installation

Paste.
Commit. Merge.

The skill is a single file, and it has to be committed in your website repo at .claude/skills/seasonal-theme/SKILL.md. Each cloud session starts from a fresh clone of the repo, so anything that isn't committed is gone in the next session.

1 · Paste into your session

Install the seasonal-theme Claude Code skill into this repo. Download https://raw.githubusercontent.com/Itzkiro/Raid-Contractor-Marketing-Wesbite-Themes/main/skills/seasonal-theme/SKILL.md to .claude/skills/seasonal-theme/SKILL.md. If that host is blocked, run git clone --depth 1 https://github.com/Itzkiro/Raid-Contractor-Marketing-Wesbite-Themes.git in a temp folder and copy skills/seasonal-theme/ into .claude/skills/. Don't edit the file and don't change anything else. Commit it as "Add seasonal-theme Claude Code skill" and push.

Under the hood: mkdir -p .claude/skills/seasonal-theme && curl -fsSL …/SKILL.md -o .claude/skills/seasonal-theme/SKILL.md, then commit and push.

  • 02
    Merge it to main

    The session pushes to its own claude/… branch. Open a PR (or ask Claude to) and merge it, so every new session starts with the skill. It's a Markdown file under .claude/, so the Vercel build and your live site don't change.

  • 03
    Check it loaded

    Open a new session on the repo and type /. seasonal-theme should be listed. If it isn't, make sure the file is at exactly .claude/skills/seasonal-theme/SKILL.md on the branch the session started from.

Commands

Every command.
Every flag.

Three commands. Plain words work too: "put up the Christmas theme", "make it snow" and "Valentine's hearts please" are all treated as the command.

CommandWhat it does
/seasonal-theme <season> [options]Installs that season's theme from the catalog, using its default end date unless you pass --ends.
/seasonal-theme offRemoves the seasonal code completely. Before expiry this ends the promo early. After expiry it is just cleanup, because the code already renders nothing.
/seasonal-theme statusReports which theme is installed, its end date, and whether it is live for visitors right now.

Options

FlagValueEffect
--endsYYYY-MM-DDOverrides the season's default end date. The theme expires at 00:00 on that date in --tz.
--tzIANA zone, e.g. America/New_YorkTime zone for the cutoff. Claude converts it to a UTC timestamp, accounting for DST.
--promo"TEXT"Promo headline for the announcement bar and offer card.
--promo-hrefpath, e.g. /offersWhere the bar's promo links to.
--terms"a; b; c"Semicolon-separated offer terms, printed on the offer card beside the price.
--densitylow | normal | highParticle count: about 10 / 20 / 32 on desktop, half that on phones.
--no-weather—Skips the falling-particle layer.
--no-bar—Leaves the announcement bar alone.
--no-card—Skips the offer card.

Recipes

Just weather, nothing else
>/seasonal-theme snow --ends 2027-01-15 --tz America/Chicago
Full Halloween campaign
>/seasonal-theme halloween --promo "Spooky-season special: $1 first month" --promo-href /offers --terms "$1 month one, then $49/mo; 12-month commitment; new customers only"
Promo bar only, no particles
>/seasonal-theme valentines --promo "Refer a friend, both save $25" --no-weather --no-card
Subtle effect on a busy site
>/seasonal-theme autumn --density low --no-bar --no-card
Summer, custom end date
>/seasonal-theme summer --ends 2027-09-02 --tz Europe/London --promo "Summer kickoff: $1 first month"
Check, then remove
>/seasonal-theme status
>/seasonal-theme off

How it expires

Checked in
the browser.

On a static or SSG site, a server-side date check runs once at build time and never runs again, so the theme would never expire. The skill hardcodes the cutoff as a UTC timestamp and compares it with Date.now() in the browser after mount. When the date passes, every visitor sees your normal site on their next page load, with no redeploy.

// Nov 1, 00:00 America/New_York (EDT, UTC-4) == 04:00 UTC const ENDS_UTC = Date.UTC(2026, 10, 1, 4, 0, 0);

The "after" screenshot was taken the way the skill verifies an install: by overriding the clock past the cutoff in a headless browser. Try the checkbox in the demo.

Mobile & density

Half on
phones.

Below 640px wide, the particle count is halved. The first screen on a phone is already crowded, and a seasonal effect shouldn't get in the way of a visitor who came to convert.

Why it's safe for production

Ten rules.
From real incidents.

The skill tells Claude to follow all of them on every install. They're why a seasonal theme won't cost you conversions, SEO or a broken page.

    Works with

    React. Next.
    Plain HTML.

    Next.js on Vercel

    A "use client" component, components/seasonal-theme.tsx, exports useSeason() and <SeasonalWeather />. Claude mounts it once in your layout or announcement bar.

    Any React app

    useSeason() branches your bar and gates the offer card. It renders only after mount, so there's no hydration mismatch.

    Static sites

    For HTML, Astro or 11ty: one deferred <script> with no framework and no build step. The live demo runs this exact script.

    FAQ

    Questions.

    Do I have to redeploy to turn it off?

    No. The cutoff is checked in each visitor's browser, so the theme disappears on its own at the end date. Run /seasonal-theme off later if you want the code gone from the repo.

    Why commit the skill to the repo?

    Claude Code cloud sessions start from a fresh clone of your GitHub repo every time. A skill under .claude/skills/ in the repo is available in every session. Anything only in a past session's container is gone.

    Does the skill file affect my Vercel build?

    No. It's a Markdown file in .claude/. Your site only changes when you run a /seasonal-theme command and merge what Claude pushes.

    What if a visitor's clock is wrong?

    The gate uses the visitor's device clock. Someone whose clock is set far in the past would still see the theme after the cutoff. That's harmless for a decorative effect. If your promo terms must never be shown after the end date, run /seasonal-theme off on the end date too.

    Will it hurt SEO or Core Web Vitals?

    Nothing seasonal is in the server HTML, so crawlers see your normal page. The particles are a few dozen CSS-animated spans in a fixed, clipped overlay, with no images, fonts or network requests.

    Can I add my own season?

    Yes. Ask in plain words, e.g. "a back-to-school theme with 📚 ✏️ 🎒 until Sept 10". The catalog is the default set, and the components take any emoji list and end date.
